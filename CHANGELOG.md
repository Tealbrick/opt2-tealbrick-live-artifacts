- S4 links: pins manifest 0.1.21 and miniapp-sdk 0.1.26 (spec 0.1.43). The viewer is the manifest `viewer` public route (`/v`, a prefix route; the handler sees the path without `/v/live-artifacts`), the header floor is the shared `VIEWER_HEADER_FLOOR`, the document-ticket key is an app secret (`ctx.secrets`), the viewer address check uses `requireViewUrl`. New ops: agent `artifact_share` (held, `public_link`, idempotency required; the address is in the answer of the approved retry), `artifact_publish` (held, `public_link`; staged data is bound to the digests the agent saw), `artifact_link_revoke` (never held); owner `link_create`, `link_revoke`, `links_list`. An agent link op answers `link_needs_hold` (403) unless the verified grant holds `public_link`. At most 5 active links per page and 50 per workspace; the owner's default lifetime applies; a version pin keeps its version from pruning. UI: Links page, Create link and Revoke on the page, review step 3, pushed sources in step 2, viewer-address status in Settings. Skill: how to ask for a link. Tests: real-SDK held flow, caps, expiry, revoke, pin, publish. Conformance fixtures for the link ops; A9 waived until conformance admits purpose `viewer`. Refs: C167, C232
- S4 review fixes: the approval is bound to the page. `artifact_share` takes a required `expect {version, htmlSha256, title}` (what the agent saw with `artifact_get`) and `artifact_publish` a required `expect {htmlSha256, title?, description?}`; the hold shows the page (title, version, size, sha256, author) and the call is refused with `page_changed` (409) if the page is not exactly that when it runs. An agent publish promotes a staged title or description only when listed in `expect`. Hold texts: a pinned version that is staged or older is flagged, a pin says the page code stays while title and data follow, `autoPublish = agent` is called out, a rollback says it is one, a missing viewer address is stated, agent text is JSON-quoted with control and invisible characters removed. The viewer route answers 503 without a views origin (no `'self'` fallback). Copy: the link table keeps only a fingerprint, but the SDK keeps the answer of a link call (with the address) sealed for 24 hours so the call can be repeated. Tests: approve-then-swap, staged title, person link ops and pause on the real SDK. Refs: C167, C232
- S4 review round 3: the link request is also bound to the pushed data link viewers see and to the list of data sources. `artifact_share` `expect` gains `data` (key and sha256 of every push source shown to link viewers, `none` if empty) and `sourcesSha256`; `artifact_get` answers `shareExpect` ready to pass. A request that is not the page as it is now is refused before a hold exists when the caller owns or made the page (the scope resolver runs before the hold decision); otherwise the hold starts with "Do not approve" and its input is flagged (`la_hold_flag`, migration 0002), so an approval of it never runs. Hold texts quote labels, products and ops; autoPublish and the link count read "at the time of this request". Refs: C167, C232
- S4 review blockers: a failed `la_hold_flag` write is no longer swallowed (the hold view throws, the SDK creates no hold, so nothing can be approved), and the early refusal before a hold applies only in the caller's own gallery (gallery id = caller id); a creator that lost its scope gets the ordinary `scope_denied`, the same as for an unknown page. Refs: C167, C232
- S4 review residual: no early refusal for anybody. The SDK runs `scope()` before the access and pause checks, so a refusal there told a caller that lost its gallery access, or a paused agent, whether a page exists. A request that is not the page now goes through the SDK checks first (`scope_denied`, paused: the same answers as for an unknown page) and then becomes a hold that starts "Do not approve" and is flagged. Refs: C167, C232
- deps: manifest 0.1.22, miniapp-sdk 0.1.27 (spec 0.1.44), conformance 0.1.19; the A9 waiver is gone (conformance 0.1.19 admits purpose `viewer`) and A9 and A12.caller_product_verified pass. An app caller's page records the verified `Caller.product` as its origin, not its display name (nothing in the app is decided by a caller's identity). The shell assets under `/v/live-artifacts/_s/` are content-hashed, so the SDK's immutable caching is safe; a test asserts the hash of every asset and that an unknown asset is not cached. Refs: C167, C232
- S6 / C238 sanitizer and copy: every agent document is sanitized on the server before it is served (preview and public link): `<link>` of every rel, `<base>`, `<meta http-equiv>`, `<portal>`, frames and objects, speculation rules, any element with a URL attribute that is not `data:` or relative (a link or form keeps its text and loses the address), and CSS `url()`, `@import`, `image-set()` (parse5; fails closed to a fixed document; depth and size limits; cached by digest). No "no network" claim anywhere: the copy now says the page cannot read your Tealbrick data or session, that in some browsers it can contact outside sites, and not to type private information into it (viewer footer, page and link steps, hold text, skill, manifest, README). SECURITY.md records R3 (a script can contact outside sites in Chrome) and R5 (link tokens in hosting logs). Dependency: parse5 7.3.0. Refs: C167, C238
- S6 hardening: backup and restore round trip on the real SDK (`test/backup.test.ts`: pages, versions, pushed data, source approvals, links as fingerprints only, view counts, hold flags and the pending hold come back row for row; neither archive holds a plaintext link token (the SDK keeps the answer of a link call, with the address, sealed under TB_KEK for 24 hours, and that sealed copy is in the archives); a restored link opens); `tb.export` carries the same tables. Performance budgets with median timings (`test/perf.test.ts`): sanitizer and viewer document path on a 1 MiB page, a page at the size cap with many updates, 50 links among 5,000 ended ones, 1 MiB of data. Canary (Chrome): a static page reaches nothing (0 requests, 0 connections) and still renders; a control without the sanitizer reaches the canary; the channels no header closes (R3) are recorded per channel, never asserted to be 0. deps: conformance 0.1.20 (drop-in; `--peers` not used because the repo is private). Refs: C167, C238
- S6 review fixes: CSS newlines (CR, FF, LF) end a string and any bad string or bad url token drops the whole CSS value; attribute and tag limits (256 per tag, 200,000 tags) are checked on the source before parse5 (an attribute bomb used to cost seconds); the page is sanitized at write time and the result stored per version (`la_version.served_html`, migration 0003), the viewer serves it and sanitizes at serve time only a row without it; an unservable page is refused with `view_not_servable`; after a restore every viewer link is ended and previews are deleted (SDK `afterRestore` hook; `SECURITY.md`); template depth, `<fencedframe>`, every attribute of an svg element read as CSS, `-moz-image-set`, more URL attributes, fixed-point verification; copy says a page can send what it shows to outside sites. Refs: C238
- S7 / C239 scriptless render: the server decides from the sanitized document whether a page runs scripts (a script element or an inline event handler; never an agent flag). A page without scripts is served with CSP `script-src 'none'` and a sandbox without `allow-scripts`, the shell frames it without `allow-scripts`, and its data is inlined at serve time: `data-tb-text="key.path"` becomes escaped text (never into raw-text elements), the shell reloads when the inlined data changes (`docRev`). A link remembers what the owner approved (`la_link.scripts_ok`, migration 0005): a link approved for a page without scripts always shows the scriptless render. The share hold of a page that runs scripts carries the exact sentence "This page runs scripts. In some browsers, scripts can contact outside sites, so viewers' IP addresses and anything they type can reach those sites."; `shareExpect.runsScripts` is required, so a page that gains scripts after the approval gives `page_changed`. The Links page and the page's link list tag a link that may run scripts; the review steps show the sentence. Tests: scriptless CSP, inlined data, exact hold text and tag, swap refused (unit and real SDK), canary (public link of a script-free page: 0 requests, 0 connections, renders; a link not approved for scripts runs nothing). Refs: C167, C239
- deps: manifest 0.1.23, miniapp-sdk 0.1.28, conformance 0.1.21 (integrity pinned for every tarball; conformance PASS). Refs: C239
- S7: the write also stores whether the page runs scripts and, if it does, the scriptless variant (`la_version.served_runs_scripts`, `served_plain_html`, migration 0006); the hold text, the share expect and the viewer read them, and judge a row without them at serve time. Refs: C239
- S6 re-check fixes: the attribute and tag limits are counted over the whole source with no context (comment closers `<!-->`, `<!--->`, `--!>`, raw-text elements in svg and math, unbalanced quotes can no longer hide a bomb); the restore is kept safe across a crash (the `afterRestore` hook records `restore_pending` in the restored file, the app writes `restore_handled` in the transaction that ends the links, `restore_pending` without it blocks every link); `la_version.sanitizer_version` (migration 0004): a stored page of an older rule version is sanitized again at serve time. Timing claims: a bomb is refused in under 100 ms; reading a stored row at serve is cheap; WRITING a legal worst case (240 KB, 60,000 anchors in a table) costs about 0.3 to 0.4 s. Refs: C238
- S7 re-check fixes: the owner's `link_create` for a page that runs scripts needs `acknowledged: true` on the server (`scripts_not_acknowledged`, 409; the UI sends it only when it showed the sentence); the whole-source limits run before `bindData` parses; the inlined data of one response is capped at 256 KiB (one visible marker `[data cut: too much for one page]`, nothing after it); the autoPublish switch and the hold text say an agent can put a different page that runs scripts under a link that already allows scripts. Refs: C239
- S8 / C238 SDK sanitizer: every agent document goes through the SDK's `sanitizeAgentDocument` (miniapp-sdk 0.1.31, manifest 0.1.25, conformance 0.1.22); the app's own `src/sanitize.ts` is gone (adapter `src/agent-document.ts`, `SANITIZER_VERSION` 4, so stored rows of S6/S7 are sanitized again at serve). The SDK rules are stricter: relative URLs, forms and every CSS `url()` are removed; only fragments, raster `data:` images and the app's `/_s/` path stay. Its whole-source precheck refuses the S6/S7 re-check bypass shapes (`<div <a <a …`, `x="<b"` runs, comment closers, svg/math raw text, unbalanced quotes) in milliseconds; they are fast-refusal tests now. Interim (the rules of miniapp-sdk 0.1.33): the app bounds every parse while parse5 builds the tree: depth (60,000 nested `<div>` cost 10 s in the SDK, now 11 ms), attributes copied by the parser and `<html>`/`<body>` attribute merging (attrs² budget 4,194,304, 2,048 per element; `<html z0><html z1>…` × 30,000 cost 26 s, `<p><b a0..a255>` + `<p>x` × 20,000 gave 39 MB in 15 s; now under 100 ms), 200,000 elements per parse, output at most max(4 × input, input + 1 MiB). Scriptless data (`fillTextSlots`) is capped at 256 KiB of SERVED (escaped) bytes per response. The tb helper goes after the `<!-- tb:sanitized v1 -->` marker and the doctype. Restore: the last handled SDK restore marker is kept outside app.db (`TB_DATA_DIR/la-restore-epoch`) and compared on every link check and at `onStart`, so a hard kill between the SDK's marker write and `afterRestore` cannot bring old links back. Known SDK false refusals (`<`+letter then 257+ words) are skipped tests until miniapp-sdk 0.1.33. Canary probes prove each script RAN (console marker). Refs: C238, C239
