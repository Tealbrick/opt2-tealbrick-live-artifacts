# Changelog

All notable changes to Live Artifacts. One section per released version (handbook §3.2).

## Unreleased (0.1.0)
- Scaffold from create-tealbrick-miniapp (template ci-v9.10); pins miniapp-sdk 0.1.25, manifest 0.1.18, conformance 0.1.18, ui 0.2.4. Refs: C160, C167
- S1 core: manifest (15 ops: 7 agent, 8 owner; scope `gallery`; read-only companions Knowledge + Task Board), baseline migration, galleries (own + shared), artifact create/update/get/list/delete, immutable versions with a live pointer, staging on shared pages, pushed data, the contract with later-stage fields refused, write-time HTML lint, limits; agents never receive values read from other apps (C88). Refs: C167
- S2 viewer path (local; served once LA-1 gives the bridge a views origin): shell + sandboxed document + data endpoint, `tbv_` tokens stored as digests, uniform 404, link version binding, viewer/preview data visibility (staged and unapproved data never shown), ETag, per-day view counts, owner preview ticket (10 min; `view_origin_missing` until LA-1), document served only into a frame (Fetch Metadata), no-egress canary suite in real Chrome (local evidence). Refs: C167
- S3 sources and refresh: owner ops source_test (sample read; scope_denied links to the source app's Configure page), source_approve (exact digest, digest_changed), source_revoke, trigger_approve (owner-enqueued SDK job `refresh`, one per page); agent op artifact_refresh (status only, 1/min/page); declarative projection; held/error/paused keep the last good data; 5 failed ticks → paused_error; kill switch is not a failure; 600 companion calls/hour budget; attention refresh_stopped / refresh_overdue. Refs: C167
- S5 owner UI: Gallery (filter chips with counts, cards, Resume refresh, Add a page by hand with lint advice), Page at `/page/<id>` (sandboxed preview or the viewer-address notice, Review and share steps, data sources with Test read / Approve / Revoke, schedule, links, versions, Make live, archive, typed delete, shared-page switch), Settings (link lifetime), standard pages with this app's words; plain sentences for every failed call. Refs: C167, C185
- ui 0.3.0 (app art for Live Artifacts, Table stacks at ≤ 480 px); THIRD_PARTY_NOTICES versions corrected (the ui kit is under the Tealbrick Software Licence, C220). Refs: C167, C185
- S4 links: pins manifest 0.1.21 and miniapp-sdk 0.1.26 (spec 0.1.43). The viewer is the manifest `viewer` public route (`/v`, a prefix route; the handler sees the path without `/v/live-artifacts`), the header floor is the shared `VIEWER_HEADER_FLOOR`, the document-ticket key is an app secret (`ctx.secrets`), the viewer address check uses `requireViewUrl`. New ops: agent `artifact_share` (held, `public_link`, idempotency required; the address is in the answer of the approved retry), `artifact_publish` (held, `public_link`; staged data is bound to the digests the agent saw), `artifact_link_revoke` (never held); owner `link_create`, `link_revoke`, `links_list`. An agent link op answers `link_needs_hold` (403) unless the verified grant holds `public_link`. At most 5 active links per page and 50 per workspace; the owner's default lifetime applies; a version pin keeps its version from pruning. UI: Links page, Create link and Revoke on the page, review step 3, pushed sources in step 2, viewer-address status in Settings. Skill: how to ask for a link. Tests: real-SDK held flow, caps, expiry, revoke, pin, publish. Conformance fixtures for the link ops; A9 waived until conformance admits purpose `viewer`. Refs: C167, C232
- S4 review fixes: the approval is bound to the page. `artifact_share` takes a required `expect {version, htmlSha256, title}` (what the agent saw with `artifact_get`) and `artifact_publish` a required `expect {htmlSha256, title?, description?}`; the hold shows the page (title, version, size, sha256, author) and the call is refused with `page_changed` (409) if the page is not exactly that when it runs. An agent publish promotes a staged title or description only when listed in `expect`. Hold texts: a pinned version that is staged or older is flagged, a pin says the page code stays while title and data follow, `autoPublish = agent` is called out, a rollback says it is one, a missing viewer address is stated, agent text is JSON-quoted with control and invisible characters removed. The viewer route answers 503 without a views origin (no `'self'` fallback). Copy: the link table keeps only a fingerprint, but the SDK keeps the answer of a link call (with the address) sealed for 24 hours so the call can be repeated. Tests: approve-then-swap, staged title, person link ops and pause on the real SDK. Refs: C167, C232
- S4 review round 3: the link request is also bound to the pushed data link viewers see and to the list of data sources. `artifact_share` `expect` gains `data` (key and sha256 of every push source shown to link viewers, `none` if empty) and `sourcesSha256`; `artifact_get` answers `shareExpect` ready to pass. A request that is not the page as it is now is refused before a hold exists when the caller owns or made the page (the scope resolver runs before the hold decision); otherwise the hold starts with "Do not approve" and its input is flagged (`la_hold_flag`, migration 0002), so an approval of it never runs. Hold texts quote labels, products and ops; autoPublish and the link count read "at the time of this request". Refs: C167, C232
